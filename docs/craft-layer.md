# 手感层目标文档（暂不实现）

本文只定目标和边界，不含实现计划。事实层与表面层见 [three-layer-framework.md](three-layer-framework.md)。

## 一、这一层是什么

句子节奏、意象密度、叙述距离、对白温度、留白位置——所有决定「这段文字读起来是不是这个作者写的」的东西。

它和另外两层的分界是硬的：**没有客观真值判据**。「这句太碎」「这段太满」不是可判定命题，它取决于上下文、类型、作者偏好和这一页要做的事。

## 二、为什么当前不做

### 用规则表达手感会失败，且已经失败过

节奏门禁曾经用数值判据（均长、长句比例、碎句比例）阻断提交，最终被迫改写成「只用于定位，不构成数字验收线」。这是手感规则做验证器的必然归宿：**要么误伤合法写法，要么被架空成建议。**

同样的失败模式适用于任何形式的手感硬约束：句长配额、修辞密度阈值、禁用词表、段落长度区间。它们能测的都不是它们想测的。

### 规则本身有成本

提示词里的每条规则都在和写作本身抢注意力。手感规则数量最多、最难判定、最常需要例外——它们是稳定性下降的主要来源，而收益是把所有模型的输出压向同一种中庸文体。

### 目标本身可能是错的

「让默认模型第一遍就写好」大概率无法靠提示词达成。代码 Agent 也不是一遍写对，它是**改得快**。该对标的不是一次成稿质量，而是从驳回到闭合的成本。

## 三、目标状态

手感不由规则承载，由**范例**承载。人学写作不靠读风格规范，靠读自己认可的稿子。

### 载体：作者已采纳的正文

项目里已有采纳后写作记忆抽取，但它记的是**结论**（「该角色说话简短」），该记的是**证据段落**（那一段实际写成什么样）。结论会被模型重新解读成规则，段落不会。

目标形态：

- 风格锚点来自**这个项目里作者真正保留下来的文字**，不是通用范文，不是模型自己的偏好；
- 以原文段落形式进入 Writer 上下文，不转写成条目；
- 随作者的接受/驳回/手改自然更新——被改掉的段落自动失去锚点资格。

### 判据：偏好，不是规则

作者的口味只通过采纳与修改暴露。因此这一层的「验证」不发生在提交前，而发生在**跨轮**：作者留下什么、改掉什么，就是下一轮的锚点。

## 四、边界（明确不做的事）

- 不设任何数值阈值门禁（句长、段长、比例、密度）。
- 不做禁用词表 / 同义词替换表。
- 不把手感问题升级为 blocker。终审的表达类观察保持 warning。
- 不用通用写作范文或模型默认审美作为锚点来源。
- 不因为手感问题触发定向修订往返。

## 五、与另外两层的接口

- 事实层的契约条目**不是**文风要求。终审不得因为正文没有逐条复述契约而判违约——这条已写进 `factContractForReview` 的 instructions。
- 表面层的 `severity: "note"` 是手感类观察的正确出口：值得说，不值得一次往返。
- 现有终审中的表达类 kind（`generic_prose`、`semantic_echo`、`voice_homogenization`、`compressed_prose`、`template_reuse` 等）属于手感层，应保持非阻断，且在规则盘点中优先复核误报率。

## 六、启动条件

在事实层与表面层稳定运行、并完成一次规则盘点（各条实际拦截率与误报率）之后再动这一层。在那之前，手感层的任何改动都无法归因。

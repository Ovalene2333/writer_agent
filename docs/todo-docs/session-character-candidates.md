# 正文人物候选与角色卡晋升边界

状态：已完成

## 数据证据

- Job `0hDloEdDb5ZYYGDp` 在“创建西琳个人故事并写三章”的正文任务中，因韩肃计划贯穿三章，直接调用 `save_character` 写入项目普通角色库。
- 第一次角色卡参数校验失败后重试，说明正文规划被误当成必须完成的角色资产工作。
- 韩肃的未来弧线与尚未发生的剧情在正文落盘前进入项目事实层；Session 资料库仅能从写作包间接找到他。

## 根因

- 稳定提示词只区分普通卡、简易卡与路人，没有区分“创作中暂定人物”和“项目权威角色资产”。
- 角色保存权限由工具是否可见决定，没有由用户本轮是否明确要求角色卡产物决定。
- 已接受正文的写作记忆提取只接受已有角色 ID，无法为正文中新出现的具名人物建立独立资料条目。

## 修法

- 为工具执行上下文增加 `candidate | simple | full` 的角色持久化意图；正文任务默认 `candidate`，明确角色卡任务才获得对应项目写入权限。
- 正文任务调用普通卡或简易卡保存时不报错重试，自动降级为 `character_candidate` Session artifact。
- 扩展既有“接受正文后写作记忆提取”，在同一次语义调用中识别有逐字证据、且不在角色目录中的具名人物。
- proposal 待审批期间候选保持 `planned`；正文实际接受后合并来源并提升为 `confirmed`。auto 与人工审批共用同一接受后入口。
- 候选资料通过 `supported_by` 关系绑定写作包或正文 proposal，并自动进入后续动态会话资料与叙事证据包。

## 验收

- 正文任务在 ask/proposal 与 auto 模式下均不写入 `characters/characters.jsonl`。
- 角色卡任务仍可正常创建普通卡；简易角色卡任务仍写入独立扮演卡库。
- 规划期的不完整角色结构可以保存为候选，不触发普通卡 schema 修复重试。
- 只有正文接受后，正文证据支持的新人物才成为 `confirmed` 候选。
- 工具 schema 哈希、稳定槽数量与动态消息槽位测试更新并通过。

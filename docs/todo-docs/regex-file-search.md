# Agent grep/regex 文本搜索

状态：已完成

## 问题

- `search_files` 只做不区分大小写的单一字面量搜索。
- 每个文件只返回第一次命中，无法定位重复句式、格式变体或一组结构相似文本。
- Agent 为了找全结果容易重复调用搜索或读取整份文件。

## 修法

- 保留 `search_files` 单一入口，默认 `literal`，显式支持 `regex`。
- 增加大小写控制和上下文行数；返回 grep 风格的路径、行号、列号、命中文本和上下文。
- 按行枚举多个结果并执行全局结果上限，报告是否截断、参与搜索的文件数和访问过滤数。
- 正则只用于文本定位；不用于解释用户语义、自动判断项目事实或绕过现有正文/卷访问边界。
- 编译失败或过长的表达式返回明确可修复错误，不静默退化为字面量。

## 验收

- 旧 `{query}` 调用保持不区分大小写的字面量行为。
- regex 能跨文件找到多个行级结果，并正确报告行列位置。
- 非法正则给出明确错误；零宽匹配不会死循环。
- 工作副本优先级、隐藏路径、独立正文引用和卷访问策略保持不变。
- 工具 schema 哈希更新，相关测试和生产构建通过。

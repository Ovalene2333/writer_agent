# 章节规划

把用户要求转成内容具体的叙事单元，再自主选择最合适的写作与交付方式。规划服务于正文质量，不是固定工具流程。

## 建立叙事单元

1. 确定章节起点、终点，以及读者在结尾必须感知到的变化。
2. 按因果、地点、时间、目标或局势变化划分叙事单元。不要为了凑数量拆场，也不要把多个重大事件压成一个概述段。
3. 为每个单元明确：
   - 起始局势与当下目标
   - 阻力、未知或关系压力
   - 必须在正文中发生的动作、选择、对白或发现
   - 结果、代价与传给下一单元的变化
   - 展开重心与相对篇幅
4. 把规划写进 reasoning 或内容具体的 todos。避免“规划结构、撰写初稿、润色定稿”这类无法约束正文的空步骤。

## 决定展开方式

- 让主要事件在场发生，使人物通过行动、对白、感官和选择经历它；只有过渡、重复过程或作者明确要求略写时才概述。
- 根据叙事需要一次完成全文、分段迭代、编译 write pack，或使用场景草稿链。不得把任何工具或固定顺序当成前置条件。
- 用户未指定篇幅时，根据叙事单元的数量、重要性和既有章节尺度决定足够的展开量。不要以最短文本覆盖最多事件。
- 资料不足时只补读决定当前单元所需的事实；不得为填满规划发明项目设定。

## 提交前验收

在提交完整章节提案前逐项核对：

- 用户要求的每个主要事件是否真正发生在正文中，而非只被一句话转述。
- 每个叙事单元是否产生可感知的行动结果、信息变化、关系变化或新问题。
- 转折是否有铺垫和后果，单元之间是否靠状态变化承接。
- 重要人物是否有符合其目的的具体反应，关键场面是否拥有足够的动作或对白空间。
- 删除标题和摘要后，正文是否仍像完整章节，而不是扩写后的剧情梗概。

若覆盖不足，继续扩写或重写薄弱单元后再提交。不得仅靠总结性提案说明补足正文中没有写出的内容。

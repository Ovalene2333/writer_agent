# 章节交付优先

## 原则

1. **先交付**：按交付项依次 `write_file`/`edit_file` 通过事实红线后落盘，再处理下一章。
2. **风格不硬拦**：warn/作者句式偏好不阻断首次交付；需要时再 `load_skill` 精修。
3. **失败切换**：同一章连续工具失败时，缩小改动（局部 edit），禁止反复全文重写烧步数。
4. **一章卡住不堵全局**：一章修订预算将尽时，先完成其余可交付项，再回来可选精修。

## 推荐路径

1. 读最小设定与角色原卡。
2. 需要时 `compile_write_pack` + 省略 content 的证据型 Writer（分工模式）。
3. 提交；若仅有风格观察/policyObservations，记录 skillId 后继续下一交付项。
4. 用户要求精修或最终润色时，再按 skill 做最小 edit_file。

## 不要做

- 不要为 warn 项循环 gate 到绝对上限。
- 不要把风格偏好扩张成绝对禁令。
- 不要在未交付任何章节前做全书风格预审。
